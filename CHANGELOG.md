# CHANGELOG

## 2026-03-06

Технические изменения:
- Закрыт RFC по рефакторингу структуры проекта (MVP выполнен).
- RFC по безопасности и рефакторингу структуры перенесены в архив `docs/archive/`.
- Незавершенные хвосты перенесены в активный RFC по операционной CLI-панели:
  - branch protection для `main` с обязательным check `security-gate`;
  - плановая ревизия и постепенное удаление root shim-модулей.
- RFC по CLI уточнен: добавлен интерактивный текстовый режим меню (`python manage.py menu`) и командный режим для автоматизации.

## 2026-03-03

Основные изменения для пользователей:
- Добавлена кнопка **«Пересечения (WebApp)»** в главное меню ролей с доступом к пересечениям.
- Для WebApp включен production-safe режим доступа: данные выдаются только при валидном Telegram `initData`.
- Локальный dev fallback по `X-Telegram-User-Id` оставлен только для разработки (через `WEBAPP_ALLOW_DEV_FALLBACK=1`).
- Добавлены инструкции и шаблоны для инфраструктуры WebApp (Nginx + HTTPS + BotFather `/setdomain`).

Что нужно сделать пользователю:
- Администратору сервера: указать `WEBAPP_URL` и настроить HTTPS-домен для WebApp.
- Для локальной отладки использовать dev fallback только на тестовом стенде.

## 2026-03-02

Основные изменения для пользователей:
- Добавлен read-only WebApp для визуализации пересечений отсутствий (по ролям и ACL).
- В WebApp добавлены пресеты периода: **текущий год / текущий месяц / следующие 90 дней**.
- Добавлена детализация интервала по клику (точные даты, статус, комментарий).
- Добавлена подсветка конфликтных дней с порогом **«Конфликт от»**.
- Добавлена выгрузка текущего вида в **XLSX** (с учетом активных фильтров и прав доступа).

Что нужно сделать пользователю:
- Открыть WebApp из бота и выбрать нужный scope/группу/период.
- При планировании отсутствий использовать подсветку конфликтных дней.
- При необходимости отправки отчета — кнопка **«Экспорт XLSX»**.

## 2026-02-19

Основные изменения для пользователей:
- Добавлена роль **Наблюдатель** (чтение): просмотр заявок, состава группы и отсутствий без прав на изменения.
- Пользователи могут запросить роль **Наблюдатель** через раздел **«Группы»**.
- Администраторы группы и суперадмины могут назначать/снимать роль наблюдателя.
- Добавлено массовое добавление сотрудников в группу (множественный выбор, пагинация, итоговый отчет).
- Суперадмину добавлен явный фильтр контекста: кнопка **«Фильтр: ...»** показывает текущий режим.
- Уведомления и пересечения для суперадмина теперь учитывают выбранный фильтр группы.
- Добавлена сервисная рассылка через CLI (`broadcast.py`) с поддержкой отправки только актуального блока changelog (`--changelog-latest`).
- Обновлены подписи кнопок и раскладка меню: интерфейс стал компактнее и проще на мобильных устройствах.

Что нужно сделать пользователю:
- Если нужен доступ только на просмотр — подайте заявку **«Группы» → «Стать наблюдателем»**.
- Если вы суперадмин, проверьте активный контекст по кнопке **«Фильтр: ...»** перед обработкой заявок.

## 2026-01-29

Основные изменения для пользователей:
- Появились **группы**: теперь доступ к функциям зависит от членства в группе.
- Добавлены **администраторы групп** (свои права внутри группы).
- Суперадминистратор управляет группами, пользователями и отсутствиями глобально.
- Обновлено меню: оно стало более структурированным и понятным.
- Появились заявки на **вступление/выход** из группы.
- Добавлена возможность добавлять отсутствие **другому пользователю**.
- При создании отсутствия отображаются **пересечения** с другими пользователями.
  Для своего отсутствия требуется подтверждение перед отправкой.
- Для администраторов добавлены ежедневные напоминания по необработанным заявкам.
- Суперадмин может посмотреть список пользователей выбранной группы.

Что нужно сделать пользователю:
- Если вы ещё не состоите в группе, откройте **«Группы» → «Запроситься в группу»**.
- После одобрения вы получите доступ к полному меню.
