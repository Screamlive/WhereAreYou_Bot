# CHANGELOG

## Март 2026 — сводка отличий от `main`

### Для пользователей

- Добавлен read-only WebApp для просмотра пересечений отсутствий.
- В WebApp добавлены пресеты периода: текущий год, текущий месяц, следующие 90 дней.
- Добавлена детализация по клику на интервал (даты, категория, статус, комментарий).
- Добавлена подсветка конфликтных дней с порогом (`Конфликт от`).
- Добавлен экспорт текущего представления WebApp в XLSX.
- В меню бота добавлена кнопка **«Пересечения (WebApp)»**.
- Добавлена сервисная рассылка с отправкой актуального верхнего блока changelog (`--changelog-latest`).

### Для администраторов и суперадминистраторов

- В WebApp закреплены ролевые ACL по scope:
  - участники/наблюдатели/админы групп — только group scope;
  - суперадмины — global/group/superadmins scope.
- Для планирования отпусков и согласования отсутствий доступен общий визуальный график пересечений.
- Для выгрузки текущего вида (с учетом активных фильтров и прав) добавлен XLSX-экспорт.
- Добавлена роль **наблюдатель группы** (доступ только на чтение) с отдельным UX в боте.
- Для суперадмина добавлен фильтр уведомлений/контекста по группе.

### Backend / эксплуатация / безопасность

- Добавлен production-safe контур WebApp auth: данные только при валидном Telegram `initData`.
- Dev fallback (`X-Telegram-User-Id`) оставлен как тестовый режим и управляется флагом.
- Добавлена операционная CLI-панель `manage.py` / `./manage`:
  - интерактивное меню;
  - управление сервисами;
  - smoke-проверки;
  - backup/restore/prune + scheduler;
  - мониторинг и тех-уведомления;
  - сервисные рассылки.
- Добавлены мониторинг-доработки:
  - anti-spam state для тех-алертов;
  - событийные алерты через `systemd OnFailure`;
  - опциональный мониторинг `nginx.service`;
  - корректный учет `--scope` в `monitor check`.
- Усилена безопасность stop фоновых процессов: PID сверяется с cmdline перед остановкой.
- Для `TOKEN` введен единый источник: окружение через `/etc/telegram_bot/telegram_bot.env`
  (или явный `export TOKEN=...` для разового запуска).
- Добавлены security headers, rate-limit и security-gate (`scripts/security_gate.sh` + CI workflow).
- Проведен рефакторинг структуры проекта: ключевая логика перенесена в `app/*`, корневые entrypoint-файлы оставлены как shim-слой совместимости.
- Актуализированы `README.md`, `DOCUMENTATION.md`, `SECURITY.md` и deploy-шаблоны.

## 2026-02-19

Основные изменения для пользователей:
- Добавлена роль **Наблюдатель** (чтение): просмотр заявок, состава группы и отсутствий без прав на изменения.
- Пользователи могут запросить роль **Наблюдатель** через раздел **«Группы»**.
- Администраторы группы и суперадмины могут назначать/снимать роль наблюдателя.
- Добавлено массовое добавление сотрудников в группу (множественный выбор, пагинация, итоговый отчет).
- Суперадмину добавлен явный фильтр контекста: кнопка **«Фильтр: ...»** показывает текущий режим.
- Уведомления и пересечения для суперадмина теперь учитывают выбранный фильтр группы.
- Добавлена сервисная рассылка через CLI (`broadcast.py`) с поддержкой отправки только актуального блока changelog (`--changelog-latest`).
- Обновлены подписи кнопок и раскладка меню: интерфейс стал компактнее и проще на мобильных устройствах.

Что нужно сделать пользователю:
- Если нужен доступ только на просмотр — подайте заявку **«Группы» → «Стать наблюдателем»**.
- Если вы суперадмин, проверьте активный контекст по кнопке **«Фильтр: ...»** перед обработкой заявок.

## 2026-01-29

Основные изменения для пользователей:
- Появились **группы**: теперь доступ к функциям зависит от членства в группе.
- Добавлены **администраторы групп** (свои права внутри группы).
- Суперадминистратор управляет группами, пользователями и отсутствиями глобально.
- Обновлено меню: оно стало более структурированным и понятным.
- Появились заявки на **вступление/выход** из группы.
- Добавлена возможность добавлять отсутствие **другому пользователю**.
- При создании отсутствия отображаются **пересечения** с другими пользователями.
  Для своего отсутствия требуется подтверждение перед отправкой.
- Для администраторов добавлены ежедневные напоминания по необработанным заявкам.
- Суперадмин может посмотреть список пользователей выбранной группы.

Что нужно сделать пользователю:
- Если вы ещё не состоите в группе, откройте **«Группы» → «Запроситься в группу»**.
- После одобрения вы получите доступ к полному меню.
