# Документация бота

## Назначение

Бот помогает фиксировать отсутствия сотрудников, согласовывать их и вести простую
историю заявок в SQLite.

## Роли

- **Пользователь** — может регистрироваться, добавлять отсутствие, смотреть свои заявки,
  запрашивать удаление/изменение одобренных заявок и добавлять отсутствие другому
  сотруднику (если его аккаунт одобрен).
- **Администратор** — дополнительно управляет пользователями, согласует заявки,
  назначает/отзывает админов, делает выгрузки.

## Регистрация и доступ

1) Новый пользователь жмет `/start` и кнопку «Зарегистрироваться».
2) Указывает ФИО.
3) Бот создает/обновляет запись в `users` с `is_approved=0` и отправляет запрос админам.
4) Админ одобряет или отклоняет.

### Если нет админа
Первого админа нужно назначить вручную в базе (см. README).

## Команды

- `/start` — приветствие и меню по роли.
- `/approve <telegram_id>` — ручное одобрение пользователя (только админ).
- `/decline <telegram_id>` — ручное отклонение пользователя (только админ).
- `/refresh_menu` — обновить меню у всех одобренных пользователей (только админ).

## Меню пользователя

- **Добавить отсутствие** — создание заявки с категорией, датами и комментарием.
- **Мои отсутствия** — список заявок и кнопки:
  - «Удалить #ID» — запрос на удаление одобренной заявки.
  - «Изменить #ID» — запрос на редактирование одобренной заявки.
- **Добавить отсутствие другому сотруднику** — создание заявки за другого
  одобренного сотрудника (с подтверждением админа).

Во всех сценариях можно нажать «Отмена» для выхода из процесса.

## Меню администратора

- **Список запросов** — заявки на регистрацию (approve/decline).
- **Список сотрудников** — список одобренных пользователей.
- **Заявки на отсутствие** — все pending‑заявки с кнопками одобрения/отклонения.
- **Выгрузить отсутствия (CSV)** — выгрузка за период (файл отправляется в чат).
- **Выгрузить отсутствия за сегодня** — список одобренных отсутствий, пересекающихся с датой сегодня.
- **Назначить админом** — выбор пользователя и выдача прав.
- **Список админов** — список администраторов.
- **Отозвать админа** — выбор администратора и отзыв прав.
- **Добавить отсутствие** — обычный сценарий добавления (как у пользователя).
- **Удалить мои отсутствия** — быстрый доступ к своим заявкам.
- **Посмотреть отсутствия сотрудника** — просмотр заявок конкретного пользователя.
- **Удалить сотрудника** — удаление пользователя из системы.
- **Удалить отсутствие сотрудника** — админское удаление конкретной заявки.
- **Добавить отсутствие другому сотруднику** — добавление заявки за другого сотрудника.

## Категории отсутствий

- `vacation` — Отпуск
- `sick` — Больничный
- `dayoff` — DayOff
- `other` — Другое

## Статусы заявок

- `pending` — ожидает решения администратора.
- `approved` — одобрено.
- `declined` — отклонено.

Удалять/изменять пользователь может только **approved**‑заявки.

## База данных

SQLite файл по умолчанию: `bot_database.db`.

Таблицы:

### users
- `telegram_id` (PK)
- `username`
- `fullname`
- `is_approved` (0/1)
- `is_admin` (0/1)

### absences
- `id` (PK)
- `user_id` (FK -> users.telegram_id)
- `category`
- `start_date` (ISO, `YYYY-MM-DD`)
- `end_date` (ISO, `YYYY-MM-DD`)
- `comment`
- `status` (`pending` / `approved` / `declined`)

### logs
Журнал действий (время, пользователь, действие).

### edit_requests
Запросы на изменение заявок (новые значения, user_id).

## Логи

Все ключевые действия пишутся в таблицу `logs` и в консоль (logging DEBUG/INFO).

```
PY
```
